## Q&A Preparation

### Expected Questions & Answers

**Q: "Why template-based Granite instead of real API?"**
> "For demo reliability and offline capability. The architecture is production-ready - we just need to swap the service implementation to call IBM watsonx.ai. The interface, prompts, and data flow are all designed for real LLM integration."

**Q: "How accurate is the debris risk scoring?"**
> "It's a relative risk indicator based on TLE data, which we clearly disclaim. TLE accuracy degrades over time due to atmospheric drag and other factors. For operational use, we'd integrate Space Force Conjunction Data Messages, which provide formal collision probabilities. But for mission awareness and early warning, TLE-based scoring is valuable."

**Q: "Why isn't Discovery integrated with alerts?"**
> "Intentional design decision. Exoplanet detection is a long-term science mission with different timelines and priorities than operational alerts. A transit candidate doesn't require immediate response like a debris conjunction or health anomaly. Keeping it separate maintains clarity of purpose."

**Q: "How does IsolationForest work?"**
> "It's an unsupervised ML algorithm that isolates anomalies by measuring how easily a data point can be separated from the rest of the dataset. Unlike statistical methods that assume normal distribution, IsolationForest works on the principle that anomalies are 'few and different' - they're easier to isolate. We use a contamination rate of 10%, meaning we expect about 10% of readings to be anomalous."

**Q: "What's the performance impact of real-time telemetry?"**
> "WebSocket streaming is very efficient. The backend generates telemetry asynchronously in a background task, and the frontend receives updates without polling. UI updates are smooth, typically 60fps, with no blocking. Memory usage is stable - we're not accumulating data indefinitely."

**Q: "How would you scale this to multiple spacecraft?"**
> "Several approaches: Add spacecraft_id indexing to all tables, implement spacecraft selection in the UI, use separate WebSocket channels per spacecraft, and potentially move to a microservices architecture where each spacecraft has its own service instance. For the database, we'd migrate from SQLite to PostgreSQL with proper indexing and partitioning."

**Q: "What about false positives in anomaly detection?"**
> "That's where the contamination rate comes in. We set it to 10%, which is tunable based on operational experience. The IsolationForest model is retrained continuously with the last 100 readings, so it adapts to changing conditions. In production, we'd also implement alert correlation and operator feedback loops to reduce false positives over time."

**Q: "Can you explain the Random Forest features?"**
> "We extract 13+ features from each light curve: BLS period, depth, SNR, duration, shape metrics (skewness, kurtosis), odd-even depth difference, secondary eclipse depth, and several diagnostic features. These capture both the transit signal characteristics and potential false positive indicators. The Random Forest learns which combinations indicate real transits versus instrumental artifacts or stellar variability."
